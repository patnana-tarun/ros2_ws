# 2026-10-15

## Done
- Startup lifecycle hang ([[Nav2 not loaded]]): both lifecycle managers now run with
  `autostart: False`. The new `lifecycle_startup` node in [[explorer_exploration]] sends them
  STARTUP after the new `startup_delay` launch argument (default 8 s). Changed
  `bringup.launch.py`, `setup.py`, and added `lifecycle_startup.py`.
- Tried first: STARTUP through `ros2 service call` from a `TimerAction`. Replaced, because the
  fresh CLI process hit the same race.
- New issue note [[GUI crashes in VS Code terminal]].
- TF at full rate on the robot, a third on the mesh ([[Relay rates]]): EKF `frequency` back to 30 Hz,
  SLAM `transform_publish_period` back to 0.02 s, robot_state_publisher back to its 20 Hz default
  (sim and real launch files), relay `tf_decimation` 1 → 3 (YAML and node default). The `/map`
  settings are unchanged. Fixed the relay docstring, which still described the old split.

## Verified
- 28 GUI launches with the discovery server: old launch 1/8 hung, CLI version 1/8 hung,
  `lifecycle_startup` 0/12 hung. Timings are in [[Nav2 not loaded]].
- Gazebo and RViz crash in the VS Code snap terminal (`__libc_pthread_init`), and the launch
  shuts down 6 s in. With the snap variables unset they opened every time.

- TF rates, 3 GUI runs: `/tf` 100–103 /s, `/mesh/tf` 33.3 /s, exactly a third per source.
- Startup turn with the EKF at 30 Hz: mean overshoot 55°, 3/3 goals reached
  ([[Baseline runs 2026-10-08]]).

## Not yet verified
- That raw `/tf` stays off the mesh with the receiver connected (the Pi was off). Check with
  `ros2 topic info /tf -v` while the receiver runs: no subscriber may be on the Pi.
- The delayed startup on the real robot (`sim:=false`) and without the discovery server.
- Whether 8 s is enough on the Pi, which is slower.
- `benchmark_headless.launch.py` (uses the same bringup, not run separately).

## Found
- Nav2's lifecycle manager calls `change_state` with no timeout (Jazzy
  `LifecycleServiceClient::change_state(transition)`), so a lost request or reply hangs it
  for good.
