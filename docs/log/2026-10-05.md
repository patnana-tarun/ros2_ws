## Found
- **`map_active` always 1** came from the sender, not the logger: the hold and the map interval were both 2 s (the row has since been removed together with the throttle, see [[Map-in-flight throttle]]).
- Scenario 1 ran before chrony synced (Pi clock at 2026-06-05, sender 121 days ahead), so every
  latency sample was excluded and the timestamps are in June. The black box has 37 reports for
  it, but the normalized CSV has only the last 22 and the main CSV has none. Both files were
  modified at 13:10–13:11, when the node was idle and not writing, so they were most likely
  edited outside the node.
- The raw event logger did not run in this test: `raw_mesh_events.csv` was last written on
  2026-09-30.
- The receiver Pi's clock read 2026-06-05 again, so `colcon build` silently kept the old
  installed node: the source files were newer than the clock ([[Known limitations]] #21).
- The user's run (screenshots): the robot was wedged between three rock halos, the controller
  reported "Failed to make progress" 7 times, and 4 goals timed out in a row.
- No recovery behaviour ever ran: two 30 s progress failures used up the coordinator's 60 s
  goal timeout, and the only recovery reached was clearing the costmaps.
- The robot (0.32 × 0.22 m, circumscribed radius 0.19 m) needs a gap of ~0.4 m to pivot.
  Gaps between chamber rocks are often narrower, so the robot can drive in but not turn.
- The user's `receiver.yaml` edits (span 6 s, Th_req 60) had no effect: they edited `src/`,
  but the node read `install/`, which still held span 20 s and Th_req 3.
- Throughput looked the same with `map_active` 0 and 1 because it is a 20 s rolling average
  ([[Run logging]]). Scenario 4 run 1: mean 38.7 KB/s (`map_active` 0) against 41.4 KB/s (1);
  TF ~4.3 KB/s, maps ~109 KB each, 6–7 maps per window.
- Errors in the user's runs (scenarios 1–4): TF received > expected in 100 of 240 rows, by up
  to 17 (PDR capped at 100 % hid it); 4 rows with map received ≠ expected by ±1; one "batctl
  tr timed out" in 608 polls (reported as empty hop count/TQ, as intended); "batctl polling
  error: I/O operation on closed file" on Ctrl+C. Empty `map_pdr_percent` in 2 rows is
  expected: no map was due yet in the first second.
- `PackageNotFoundError: ... mesh-nodes` on `ros2 run`: the user's terminal on the Pi was
  sourced at 13:00, before the `--symlink-install` rebuild at 15:08, so its `PYTHONPATH` lacked
  `build/mesh_nodes`, where the package metadata now lives. A freshly sourced shell found it
  (version 0.1.0). No code change needed ([[Run logging]]).
