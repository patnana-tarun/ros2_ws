## Found
- The controller's "7 Hz" is only the first cycle after a costmap clear; it runs at 14.6 Hz.
  The real problem is MPPI stalling where NavFn's round-robot path can't be driven by the
  rectangular footprint ([[Path tracking and stalls 2026-10-18]]).
- `ros2 topic list` / `hz` (with or without the daemon) sees no sim topics in discovery-server
  mode, but an rclpy node started from the same shell does.
- Sim nodes also bind DDS sockets on the phone tether's address (10.144.47.177).
- Rendering wasn't the bottleneck. Using the GPU freed CPU overall, but the controller rate,
  Gazebo's CPU use and the stuck-robot warnings stayed the same (one run each, so these numbers
  are rough).
- The coordinator sent its first goal about 1.5 s before Nav2 was active. It was rejected and
  re-sent 3 s later, so it did no harm.
- `bringup.launch.py` opens two RViz windows (`explorer.rviz` and Nav2's default view), both named
  `rviz2`.
